# A spreadsheet engine (experiment)

A public demo for an experiment: the same spec built by the same AI harness, once with cooknship and once without.

The only spec is [SPEC.md](SPEC.md).

## Use

Requires Node.js (>= 18). No dependencies, no build step.

- Engine CLI: `bin/engine book.json` or `bin/engine - < book.json`; `bin/engine - --cell Sheet1!H1` prints one cell.
- UI: open `ui/index.html` in a browser (no server needed). Click or arrow keys to select, type or Enter/F2/double-click to edit, Enter/Tab to commit, Esc to cancel, Delete to clear. The formula bar shows the selected cell's formula and, for errors, what the error means. Open reads `.json` workbooks and `.csv` files; Save JSON keeps formulas, Save CSV writes the current sheet's computed values. Double-click a sheet tab to rename it.
- Tests: `./test.sh` runs the whole suite: engine fixtures whose expected values were computed by LibreOffice, CLI checks, CSV checks, and a UI smoke test in headless Chromium (skipped if no Chromium is installed).

## Layout

- `src/engine.js` — tokenizer, parser, evaluator and the functions (runs in Node and in the browser): the spec's 40, plus PI, COUNTBLANK, PROPER, EXACT, VALUE, FIND, SEARCH, ISNA, ISERR, ISLOGICAL, ISNONTEXT, N, T, SIGN, TRUNC, REPT, SUBSTITUTE, CHAR, CODE, CHOOSE, ROWS, COLUMNS, OFFSET, ISREF, SUMPRODUCT, COUNTIFS, SUMIFS, AVERAGEIFS, HLOOKUP, EXP, LN, LOG, LOG10, FACT, ISODD, ISEVEN, EVEN, ODD, QUOTIENT, CEILING, FLOOR, VAR, VARP, STDEVP, LARGE, SMALL, RAND, RANDBETWEEN, TEXT (number formats, no dates or fractions), ROW, COLUMN. Unknown functions give `#NAME?` after their arguments are computed (a computed error argument wins), as in Calc.
- `bin/engine` — the CLI.
- `src/csv.js` — CSV import/export; `ui/` — the browser UI.
- `tests/src/*.txt` — formula lists; `tests/cases/*.json` the workbooks built from them; `tests/expected/*.json` LibreOffice's results.
- `tools/lo_oracle.py`, `tools/probe.sh`, `tools/fuzz*.{js,py}` — dev-only: regenerate expected values with LibreOffice headless.

## Semantics notes

- Expected values come from LibreOffice recalculating the workbook and writing it out (the oracle in `tools/lo_oracle.py` round-trips through xlsx). In that output Calc's internal errors without an Excel name — `Err:502` (invalid argument, e.g. `SQRT(-1)`, `MID("abc",0,1)`) and `Err:522` (circular reference) — appear as `#VALUE!`, and the engine reports them the same way.
- Numbers in the output are rounded to 15 significant digits as Calc writes them (the shortest round-trip decimal, rounded half up), and integers below 2^53 are written exactly.
- Arithmetic follows Calc's rounding: `+`/`-` snap results that cancel to within 2^-48 to 0 (but never between exact integers), and SUM/AVERAGE/SUMPRODUCT use Calc's Kahan summation (parameters taken last to first; SUM sums each range column on its own, blocks of 8 values in SSE2 lanes, the last term added with the same snapping), so `SUM(0.1,0.2,-0.3)` is 0. Inline and computed arrays are searched with exact number equality, cell ranges with approximate equality.
- An empty argument (`SUM(1,)`, `LEFT("abc",)`) is 0 as in Calc; references can be intersected (`A1:B3 B2`, a disjoint intersection is `#NULL!`) and joined (`SUM((A1:A2,B1))`); 3D references (`SUM(Sheet1:Sheet3!A1)`, also `'Sheet1:Sheet3'!A1`) cover the sheets between, in workbook order. The range operator across sheets makes one too (`SUM(Sheet1!A1:Sheet2!B2)`; an unqualified reference after a qualified one is on its sheet: `Sheet2!A1:B2:A3`); ROWS/COLUMNS count every sheet's rows/columns, INDEX gives `#REF!`, and in a scalar position only the formula's own sheet is intersected. A number literal outside the double range (`1E309`, `1E-400`) makes the whole formula an error (`#VALUE!`), and a number running into letters (`2x`, `1E5E5`) is an unknown name (`#NAME?`).
- Calc's internal errors without an Excel name are kept apart inside the engine (`Err:502` invalid argument, `Err:504` parameter error, `Err:508`-`Err:511` formula syntax, `Err:522` circular reference): the output shows them as `#VALUE!`, but text criteria see their own text (`COUNTIF(A1,"Err:502")`, `COUNTIF(A1:A9,"*a*")` does not count `SQRT(-1)`). `tests/cases/errcodes.json` checks the code of about 750 `#VALUE!` results from other fixtures (the code is read with COUNTIF in LibreOffice).
- STDEV/VAR take deviations from the mean with Calc's snapping subtraction, so equal values give exactly 0 (`STDEV(0.1,0.1,0.1)`). Numbers that round past the largest double when written with 15 digits (`="1E400"+0`) are written as 1.7976931348623157e308.
- Calc's compiler limits hold: parentheses nest at most 98 deep (`Err:514`), a formula has at most 8191 tokens and a function at most 255 arguments (`Err:512`); files show both as `#N/A`. The CLI computes on a thread with a large stack, so formulas up to those limits evaluate.
- Over arrays, division and MOD check the divisor first as Calc does: a zero divisor is `#DIV/0!` even when the dividend is an error (`SUM(SQRT({-1,4})/{0,0})`, `A1:B3/{0,0}` where the intersection fails), as is text divided by a scalar 0; an error element to the power 0 is 1. An error element of an array given as a lookup value is checked after the column/row index, as a cell's error. MID pops its text after checking position and length, so an error constant there wins (`MID(#N/A,1,-1)` is `#N/A`; `LEFT(#N/A,-1)` is `#VALUE!`).
- SUMIF/AVERAGEIF take an inline or computed array as the sum range, element by element at the criterion cell's position (positions it lacks are skipped). MATCH given a lookup array that is neither a reference nor an array is `#VALUE!`.
- SUM and AVERAGE over an array holding errors report what Calc's Kahan sum meets: the first error going column by column, unless the last non-zero element is an error, which is added last and wins (`SUM({1,2}/{0,"a"})` is `#VALUE!`, `SUM({1,2;3,4}/{0,"a";1,1})` is `#DIV/0!`); other aggregates report the first error. MIN/MAX count an array without numbers as 0. NOT over an array keeps numbers inside, and its result is shown as a boolean. A function that gives a reference keeps it beside an inline array (`SUM(IF(1,A4,{1,2}))` is 0). VLOOKUP/HLOOKUP, like MATCH, take a function-made array lookup value whole; an element taken from a function-made array into a scalar parameter is an operand whose error behaves like a cell's (`SUM(ROUND(SQRT({-1,4}),#N/A))` is `#N/A`). `1^x` and `x^0` are 1 between arrays whatever the error.
- CHOOSE given an array index (`CHOOSE({1,2},B1:B3,A1:A3)`, also a function-made one: `CHOOSE(ROW(A1:A2),10,20)`) picks element by element like an array IF: ranges in the chosen branches are taken as arrays (so `VLOOKUP(20,CHOOSE({1,2},B1:B3,A1:A3),2,0)` searches column B and returns from column A), an index out of range or text is `#VALUE!` in its element, and branches no element takes are not computed. ROW/COLUMN of a range several rows/columns across are arrays to operators (`SUM(ROW(A1:A3)*1)` is 6).
- `^`/POWER results that underflow to a subnormal number or zero are `#NUM!`.
- Text functions count Unicode code points; `CHAR`/`CODE` use UTF-8 like Calc on Linux (`CHAR(233)` is U+FFFD).
- Booleans are numbers with a boolean format, as in Calc: `TRUE+1` is 2, `TRUE&""` is `"1"`, and a result is reported as `true`/`false` when Calc would format it as a boolean. Negation keeps the format (`-FALSE` is `false`) except for a reference, a value IFERROR passes on or one INDEX takes from an inline array (`-IFERROR(FALSE,0)` is 0).
- An array IF without an else branch leaves an "empty path" element where the condition is false: aggregates skip it, as a value it is FALSE (`=IF({0,0},1)` is `false`, `&"x"` gives `"FALSEx"`, as a number 0). AND/OR given an array with an empty element are `#VALUE!`. INDEX given an array of positions takes, for each element, the cell of the referenced row/column at that element's position (`INDEX(A1:B3,{1,2},0)` is A1 and B2).
- Inline arrays hold numbers (one sign at most), text and TRUE/FALSE stored as the numbers 1 and 0 (`={TRUE}` is 1); an empty element (`{1,,2}`, `{}`) is an empty matrix element (skipped by COUNTA, empty text through INDEX); errors or expressions inside braces are a syntax error, shown as `#N/A`.
- An empty argument that IF, CHOOSE or IFERROR returns (`IF(1,)`, `IFERROR(1/0,)`) stays Calc's missing value: 0 as a number and in lookups or criteria, `""` as text (`IF(1,)&"x"` is `"x"`), blank for ISBLANK, neither number nor text; a cell holding one is an empty result (shown 0). `IFERROR(,x)` passes one on that ends as an error shown `#N/A` (not ISNA).
- An empty text constant (`""`) in the input is an empty cell.
- An error constant in a formula (`=#N/A`) is a plain error token, not a pending error (`SUM(#N/A,1/0)` is `#DIV/0!`); IF, CHOOSE and IFERROR (its fallback) pass it on as it is, other functions make it pending. As Calc pops parameters, an error token overwrites the error a cell or a conversion set, so among several the leftmost wins (`ROUND(#N/A,#NUM!)`, `#N/A<#NUM!` are `#N/A`), except in CONCATENATE and MEDIAN, which take parameters first to last (the rightmost token wins). As a lookup value, table or INDEX reference it gives `#VALUE!` (the reference: its own error) after the other parameters' errors; OFFSET gives `#VALUE!` after its other arguments' errors; SUMIF/AVERAGEIF check the sum range first (anything but a range is `#VALUE!`), COUNTIF reports an error constant given as its range. `#REF!` and unknown `#words` read as unknown names (`#NAME?`), and an `_xlfn.` prefix is not stripped, as in LibreOffice's xlsx import.
- A lookup (MATCH, VLOOKUP, HLOOKUP) whose lookup value is a computed `#N/A` gives Calc's internal lookup error: shown as `#N/A`, but `ISNA` is false and `ISERR` true. A `#N/A` read from a cell stays a plain `#N/A`. Any computed error as the lookup value gives such an internal error (shown with its own code): once a later function clears the pending error it reads as `#VALUE!`. A blank lookup value looks for empty text (a formula's `""`); a blank or empty-result cell that VLOOKUP/HLOOKUP return is 0 as a number and `""` as text.
- SUMPRODUCT's arguments and the table argument of MATCH/VLOOKUP/HLOOKUP are evaluated as arrays (`SUMPRODUCT((A1:A9>1)*B1:B9)`); elsewhere a range in a scalar position is intersected with the formula's row or column (a block on another sheet with both: the cell at the formula's own position), as in Calc. Inline arrays stay arrays in any formula (`SUM({1,2}*{3,4})`, `SUM(LEN({"a","bb"}))`, `IF({1,0},...)`), with ranges beside them still intersected by operators (and POWER), while a function given an array in one argument takes a range argument as an array too (`SUM(MOD(A1:A3,{2,3}))`, `SUM(IF({1,0},A1:A3,B1:B3))`); a comparison with an array takes a multi-cell range operand as an array too (`COUNT({1,2}<>A1:B3)` is 6), and comparing an array with an error gives that error; an array IF condition's text elements are errors; a function applied element by element is as large as its largest array argument (`#VALUE!` where a smaller one lacks the position; for IF the condition's size holds where it is above 1, `#N/A` where the chosen branch lacks the position) while operators stop at the smallest; POWER follows `^`; Calc's NOT takes a function-made array whole (errors and non-numeric text give 0); an array given as a COUNTIF/SUMIF/AVERAGEIF criterion, a MATCH/VLOOKUP/HLOOKUP lookup value or an INDEX position gives one result per element (`SUMPRODUCT(1/COUNTIF(A1:A9,A1:A9))`). `@A1:A3` is the implicit intersection. In an ordinary formula an array made by a function reaches another function's scalar parameter as its first element (`SUM(ABS(LEN({"a","bb"})))` is 1, as in Calc), unless an inline array is another argument of that function (`SUM(ROUND(LEN({"a","bb"}),{0,0}))` is 3), while operators, IF/IFERROR and aggregates take it whole; comparing arrays of different sizes fills the missing positions with `#VALUE!`; array-and-scalar `^` treats text and errors as NaN (`#NUM!`, but `x^0` is 1).
- An ascending approximate lookup over cells with a wildcard pattern (`VLOOKUP("b*",A1:B9,2)`, `MATCH("*y",A1:A9,1)`) takes the first cell the pattern matches (extended over the matching cells right after it); with no match it is a sorted search comparing the pattern as plain text. Over inline arrays the pattern is always plain text in a sorted search.
- MIN/MAX pass over an array parameter holding an error, other than the first parameter, entirely (`MIN(5,SQRT({-1,4}))` is 5, `MIN(SQRT({-1,4}),5)` is `#VALUE!`), as Calc's matrix minimum is NaN there.
- A cell that reads a cell of a reference cycle still being computed gets Err:522, unless a formula on the way from that cell to the read already computed an error that is still pending: then it gets that error (`A1: =B1+1/0`, `B1: =A1` makes both `#DIV/0!`; with `=ABS(B1)+1/0` both are `#VALUE!`). A reference operand is read when its operator runs, the right one first, and the arguments of IFERROR's value, the IS functions, COUNT and N are computed with no pending error, as in Calc. N given a lookup's internal error (`N(VLOOKUP(1/0,A1:B3,2,0))`) is `#VALUE!`.
- SUM reports range errors the way Calc's per-column sum meets them: in the first column holding an error, the first error of the last run of formula cells (booleans count as formula cells, as after an xlsx import) that has one.
- Calc's interpreter stops at the first error unless the formula still holds an error function (COUNT, COUNTA, N, IFERROR, the IS functions) that has not run yet, wherever it is, even in a branch that is never taken; the engine models this: past such an error the error is an ordinary token (`MOD(SQRT(-1),0)+COUNT(1)` is `#DIV/0!` while `MOD(SQRT(-1),0)` is `#VALUE!`; `MOD(IF(NA(),1,COUNT(1)),0)` is `#DIV/0!`, an IF with an error condition passing it on as a token; a lookup given such a token gives `#VALUE!`), and a result that is not an error token still ends as that first error unless an error function cleared it.

## Known deviations

Approximate-match lookups (`VLOOKUP(..., TRUE)`, `HLOOKUP(..., TRUE)`, `MATCH` with type 1 or -1) agree with LibreOffice on sorted data. On unsorted data the engine models Calc's search (a binary search down a column that goes on past an exact hit, then a walk while cells satisfy the condition, numbers sorting before text): unsorted columns or rows of only numbers or only text agree with LibreOffice in all of about 20000 random lookups; columns mixing numbers, text and booleans about 98% of the time.
SUM over ranges mixing very large and tiny values can still differ from LibreOffice in the last digit (a few in a thousand such random sums).
Deeply nested formulas mixing inline arrays, text and errors agree with LibreOffice about 99% of the time on random cases (which error is reported, and the number/boolean format of array elements).
Circular references through lookups: like Calc, a lookup over cells computes only the cells its search reaches, so a lookup over a range holding its own cell need not be circular (`tools/fuzzlkcyc.js`: about 99% agreement). Calc recomputes some cells of a cycle once it unwinds, which the engine does not model.
Calc keeps a pending error: the first error computed in a formula wins over later ones, unless a function that resets it (IFERROR, ISNUMBER, ISTEXT, ISBLANK, ISERROR, ISERR, ISNA, ISLOGICAL, ISNONTEXT, COUNT, COUNTA, N) runs afterwards; the earlier error is then an ordinary operand (`IF("z",1)+IFERROR(2,1)/0` is `#DIV/0!`). The engine models this per formula cell. A scalar error computed among array operations (`2^({1,2}*NA())`, `2^(0<=-{1,2}--A4)`) is likewise the result, while an error inside an array element is not, nor one in an array IF branch that no element takes, nor one a branch makes in its last operation (`IF({1,0},1,NA())` is 1, `IF({1,0},1,NA()+1)` is `#N/A`: there the error went through another operation).
When a single function call meets several different errors at once (for example an error argument and an invalid argument), LibreOffice's choice of which error to report depends on interpreter internals; the engine follows the common cases (first error computed, then arguments examined last to first) but not every combination.
